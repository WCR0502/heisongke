# 设计稿接入对照表 · 第三轮 UI 改版

> 交付物：把 5 张设计稿（`2026年10月21日 20_05_45.png` ~ `20_06_07.png`）接进现有演示版。
> 只改「视觉层」：`index.html` + `assets/css/console.css`，**五个 JS 文件一行未动**。
> 样式版本：`console.css?v=71`

---

## 0. 一句话结论

5 张设计稿 → 5 个 `.screen` 分页，**逐屏一一对应**；顶栏导航只有 4 个标签，因为设计稿把「症状梳理」画成了一页，
而实现里这一页由 `ask`（追问）+ `result`（建议）两屏组成——用「双 step 位 + 单标签」的办法消化掉了这个差量（见 §5.1）。

JS 共引用 **84 个 id**，全部保留，`clearDeptFilter` / `reciteTip` 两个由 JS 运行时动态插入，属预期缺失。

## 5. 无法直接一一对应的部分（原因 + 替代方案）

### 5.1 设计稿的「症状梳理」是 1 页，实现是 2 屏（ask + result）

- **差量**：设计稿导航 4 个标签，流程却有 5 步；稿子里「症状梳理」同时包含了追问和建议结果。
- **做法**：导航只渲染一次「症状梳理」，但在 DOM 里放两个 `.step`——可见的 `data-step="ask"` 和一个
  `0×0`、`opacity:0` 的 `.step-dup[data-step="result"]`，两者同处 `.nav-slot` 容器。
  这样 `go()` 对 `result` 的 `on/done` 赋值仍然有落点，界面上永远只看到一个标签。
- **若要严格一页**：需要把 `result` 的内容并进 `ask` 屏并改 `SCREEN_ORDER`，属于改业务逻辑，本轮不做。
  建议保留现状——「先追问、再给结论」两屏的信息密度更接近真实医疗流程。

### 5.2 顶栏导航不可点

- **原因**：设计稿只画了选中态，没定义点击跳转；而流程有前置校验（没填症状就跳到「我的档案」会得到空卡）。
  `go()` 是 IIFE 内部函数，未挂到 `window`，样式层无法调用，也不宜为此改 JS。
- **替代**：所有页面都提供了合法的前进/后退按钮（`.ask-actions`、`.screen-actions`）。
- **若要可点**：在 `booking.js` 末尾加一行 `window.__go = go;`，再给 `.step` 加点击即可（2 行改动，随时可做）。

### 5.3 首页医生/患者插画没有源文件

- **原因**：设计稿是整张位图，人物插图无法单独导出；直接裁图会带底色、抗锯齿边缘与横幅渐变打架。
- **替代**：按设计稿构图手绘了一版内联 SVG（`.hero-art`）：患者线稿 + 心电对话气泡 + 白大褂医生（红心）+ 心电小卡，
  颜色全部取自设计稿色板（`#2f9d7c` / `#7fd6b8` / `#e8615f`）。矢量、可缩放、离线可用、无额外请求。
- **要换成位图**：把 `<div class="hero-art">…</div>` 内部换成 `<img src="assets/img/hero.png">`，`.hero-art{width:400px}` 不变即可。

### 5.4 「林」头像没有账号体系

- **原因**：演示版没有登录，设计稿里的头像只是占位。
- **替代**：`.avatar` 静态显示「林」，无点击、无菜单、`aria-hidden`。
- **接真实账号时**：替换成 `img.avatar` + 绑定 `#userMenu` 即可，样式已就位（30px 圆形）。

### 5.5 设计稿里的静态数字（86% / 80% / 2/5 / 0 步 / 「2 天」）

- **原因**：稿子里的进度与统计是配图数字，实现端没有对应计算源。
- **替代**：全部作为静态文案写在 HTML 里，**不参与任何逻辑**；只有真正可算的两处保持动态：
  `#followupProgress`（第 N 问）、`#answeredCount` / `#followupTranscript`（已答条数）、`#aptStats` 四指标（真实 POI + 号源）。
- **要接真实数据**：把这些数字改成 `<b id="xxx">`，在 `booking.js` 对应节点赋值，样式无需再动。

### 5.6 折线/波形装饰图（`.mini-trend`、`.sense-trend`、`.stat-line`）

- **原因**：设计稿里的曲线是装饰性配图，没有数据来源，也没有坐标标注。
- **替代**：内联 SVG 写死 `path`，纯装饰（`aria-hidden="true"`），不请求接口、不参与计算。
- **要做成真图表**：保留容器，用 `<canvas>` 或 SVG 动态生成 `path`；`.mini-x` 轴标签可复用。

### 5.7 字体

- **原因**：设计稿用的是 Inter / DM Sans 这类西文字体，本机不一定有，且演示版要求离线双击可用，不宜引 web font。
- **替代**：`PingFang SC → HarmonyOS Sans SC → Noto Sans SC → Microsoft YaHei → system-ui` 的中文栈；
  英文标题（`M E D E C H O`）用 `letter-spacing` 拉开字距模拟设计稿的几何感。
- **要精确还原**：把字体文件放 `assets/fonts/`，加 `@font-face` 并把 `body` 的 `font-family` 首项换掉。

### 5.8 设计稿的卡片质感（微高光 / 玻璃感 / 细腻阴影）

- **原因**：位图里的柔和渐变与内高光无法逐像素复制。
- **替代**：纯 CSS 近似——`linear-gradient` 叠加 + 多层 `box-shadow`（外投影 + 1px 内高光），
  横幅用 `--hero-grad` 三段渐变（`#eafaf3 → #d9f4e9 → #c9eee0`）贴近稿子。
- **要更像**：给 `.card` 加 `backdrop-filter:blur(6px)` 或叠加一层 `radial-gradient` 白高光，代价是低端机掉帧。

### 5.9 设计稿未画的状态（本轮补上的部分）
